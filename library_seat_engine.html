7DAA lab: optimal vs greedy, and correctness checks

Batch assignment. At exam time hundreds of students want seats at once. Greedy serves them in arrival order and gives each the best seat still free, O(n·m). The Hungarian algorithm assigns all n students together and gives the minimum total mismatch, O(n²·m). Mismatch cost = wrong floor (4) + wanted quiet zone but not in it (5) + wanted a socket but none (5) + distance from the preferred table. m = 480 seats.

Why greedy is not always optimal. Two students, two seats, cost matrix [[1,2],[1,100]]:

Why Hungarian is optimal: it keeps potentials ui, vj with ui+vj ≤ costij and uses only tight edges, so its final cost equals Σu+Σv, a lower bound on every possible assignment (LP duality). Where each is used here: single online requests use greedy first-fit (people arrive one by one and cannot be reshuffled); a batch rush, such as pre-registered exam-week students, can use Hungarian.

Why bitmasks work: a day has 12 hourly slots, so each seat's whole timetable fits in one integer. Checking a range is a single AND, so cost does not grow with the number of bookings, while the naive version slows down as B grows.

Capacity: 3 floors x 40 tables x 4 seats = 480 seats = 5760 seat-hours per day. 5000 students wanting 1-4 hours each exceeds that, so the waitlist and fair allocation matter. Change F, R, C at the top of the script to match the real library layout.

Limitations: student data is synthetic; the gate scanner is simulated on screen (a real gate would read the same QR text with a camera).
